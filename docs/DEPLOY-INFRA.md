# Render deployment with Supabase PostgreSQL

`render.yaml` keeps the six existing Free resources during cutover but enables auto-deploy only for `arko-internal`. The unified service serves the public site, internal dashboard, finance, portal, PM, and API at paths on `https://arko-internal.onrender.com`. The other five services remain available for rollback, with auto-deploy off. There is no Render database or custom domain in the Blueprint. CI builds the unified web app, and Render deploys it after passing checks.

## Cutover

1. **Do not remove the old services until the unified service is working.** This cutover Blueprint retains `arko-api`, `arko-site`, `arko-finance`, `arko-portal`, and `arko-pm` with auto-deploy off. Review the sync preview before applying it. Retire them only after the checks below pass. While they remain active, their running time still consumes the workspace's shared Free hours.
2. Verify `DATABASE_URL` and `DIRECT_URL` on `arko-internal` point to the same Supabase project, with `schema=arko`. Use Supabase's IPv4 pooler endpoints for Render. The previously shared database password was exposed; rotate it in Supabase and update the Render variables. Do not paste the new password into chat or commit it.
3. Keep `AUTH_SECRET` stable, set `AUTH_URL` and `NEXT_PUBLIC_APP_URL` to the actual Render hostname, and set `ARKO_SURFACE=unified`. Set `RATE_LIMIT_SECRET`, `RESEND_API_KEY`, and any S3/AI integration variables the features need. During cutover, the hourly email scheduler still calls `arko-api`; leave its `CRON_SECRET` and `RESEND_API_KEY` in place. Once the unified endpoint is verified, change the workflow URL to `arko-internal` and set the same strong `CRON_SECRET` there and as the `ARKO_CRON_SECRET` GitHub Actions secret. Existing Blueprints might not prompt for newly added `sync: false` variables, so check them manually.
4. Back up Supabase and check Prisma migration status before applying anything. The previously observed pending migrations were `20260820000000_add_nex_send_and_reminder_permissions`, `20260926000000_pm_required_deadline_review_gate`, and `20260927120000_add_app_sessions`. The PM migration sets six missing task deadlines to their creation dates, as chosen, and may make those tasks overdue. After reviewing SQL and data, run `pnpm --filter @arko/db db:deploy` manually. No migration runs during Render build.
5. Check `/health`, public `/`, `/auth/login`, staff `/dashboard`, finance `/dashboard/finance`, client `/dashboard/client-portal`, PM `/dashboard/pm`, and the hourly email workflow. Confirm staff and clients cannot access each other's protected data. The `/health` endpoint only proves the process is running; it does **not** prove database login works.

When a custom domain is ready, add it to `arko-internal` in Render, configure DNS with the domain provider, verify TLS, and update `AUTH_URL` and `NEXT_PUBLIC_APP_URL`. Do not switch those values to `app.arkodevph.com` until that name resolves and Render verifies it. Free Render services sleep after 15 minutes idle; keeping this one service awake all month uses almost the entire 750-hour allowance.
